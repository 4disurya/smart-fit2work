## 2. API & Mock
- Global `USE_MOCK` di `index.html` (default **`false` = live** ke `window.GAS_ENDPOINT`; set `true` kembali ke mock lokal untuk dev) hanya untuk **API** (login/save/list/stats/addEmployee). Bluetooth **tidak** ikut mock — `navigator.bluetooth.requestDevice()` tetap dicoba asli lebih dulu; pencarian karakteristik kini **lintas service** (jika service utama tak ada, semua primary service di-scan untuk kandidat UUID), baru jika nihil kartu masuk **Terhubung (Simulasi)** dengan alasan tampil di kartu (`d.note`) + log. Termometer memakai `chars: [0x2A1C, 0x2A1E]`. Memilih alat BP di kartu Termometer menghasilkan pesan "bukan termometer" (daftar service UUID ikut dicatat).
- `optionalServices` kini **diperluas** (profile + service medis SIG + vendor `0xFFE0/0xFF00/0xFFF0/0xFE00` + modul oximeter 128-bit umum) — Chrome **hanya** mengizinkan akses service yang terdaftar di situ, tanpa itu service custom alat tak terlihat dan kartu langsung simulasi.
- Jika char profil tidak ada → fallback **sniff**: pilih char notify/indicate **kustom (non-SIG)** dari service yang boleh diakses (skor: notify > indicate, kurangi char write), di-log `sniff kustom <uuid> @ <service>`; frame-nya tetap melewati parser + `plausible()` (angka salah tidak mungkin lolos). Jika nihil → pesan error memuat **Inventory** `svc[uuid:props …]` untuk laporan teknisi. Char SIG (mis. `00002a37` HR) sengaja tidak di-sniff agar data alat lain tak pernah terbaca.
- Pengukuran jalur asli **tidak pernah** menampilkan angka palsu: parser wajib lolos `plausible()` + cek `recordedAt` (frame >30 menit / riwayat lama diabaikan; jam alat <2020 dianggap segar). Jika alat tak mengirim data valid dalam 120 detik → error + tombol **Coba Lagi**, form tidak diisi, field manual tidak dipaksa.
- Alat yang **tidak pernah mengirim notifikasi** (mis. Yuwell YHW-6) diambil lewat **polling `readValue()`** tiap 2 dtk dalam jendela 120 dtk (timbangan dipol **maks 1 dtk** — `Math.min(BT_POLL_INTERVAL, 1000)`, jendela hasil alat hanya ±3 dtk): baca **baseline** sekali di awal, frame diterima hanya bila hex ≠ baseline ATAU `recordedAt` segar ATAU baseline tidak terbaca; notifikasi tetap primat; timeout menyebut jumlah bacaan/notifikasi + hint urutan (tekan tombol → ukur). Tanpa notifikasi & tanpa `read` → error cepat. Log mencatat `baseline hex …`, `#N hex … → DITERIMA/sama dengan baseline/riwayat lama`. **Pengecualian `key === 'scale'`: baseline DILEWATI** (read IF_B2A = buffer nol, bobot hanya lewat notifikasi; baseline menambah jeda hingga 4 dtk + membuat nilai read identik ditahan oleh logika "sama dengan baseline") → log `baseline dilewati (timbangan: bobot lewat notifikasi)`, `baselineHex` tetap null sehingga polling menganggap semua bacaan "berubah".
- Semua `readValue` (baseline & polling) dibungkus **`BT_READ_TIMEOUT` (4 dtk)** oleh helper `btReadValue()` — read yang menggantung tidak pernah membekukan pengukuran; bila timeout baseline → `baselineHex = null` → bacaan valid pertama diterima.
- **Pengecualian stabil SPO2:** alat bisa sudah menampilkan hasil sebelum tombol ditekan sehingga nilai di char identik dengan baseline — untuk `key === 'spo2'` nilai stabil yang lolos `plausible` **diterima setelah 2 pembacaan berturut** (`BT_SPO2_STABLE_READS = 2`, ±4 dtk), log `DITERIMA (nilai stabil di alat)` / `via polling read (nilai stabil di alat)`. BP & termometer tetap wajib berubah (nilai tersimpan lama = data pasien lama, jangan diterima).
- Parser termometer menerima multi-format payload `0x2A1C`: FLOAT32 (spesifikasi SIG, °F dikonversi bila flag) → SFLOAT16 → int16÷10 → int16÷100; kandidat pertama dalam rentang 20–50 °C yang menang, format & daftar kandidat ikut di-log (`format`, `cands`).
- Parser SPO2 **SpO2-first, PR tidak wajib**: SFLOAT@1 dalam 50–100 (payload <5 byte tidak melempar — PR `null`), payload 2-byte memakai `u8@1`; `plausible('spo2')` cukup SPO2 saja. PR oximeter hanya untuk log, **tidak pernah** mengisi form (kartu SPO2 tak menyentuh `heartRate`), dan Simpan tidak mewajibkan PR (`canSave` tanpa `heartRate`). Kandidat mentah `u8@3/u8@4` ikut di-log — baris `frame` kini mencantumkan `values` bahkan saat `GAGAL` (bahan perbaikan offset alat non-SFLOAT).
- **Kandidat u8 (alat non-SFLOAT, mis. paket 5-byte gaya oxycare `spo2 = byte4`)**: bila SFLOAT@1 tak lolos, parser menyiapkan `values.cand` = kandidat `u8@1`/`u8@4` dalam 50–100. Frame kandidat **belum** `ok` — hanya diterima setelah kandidat yang sama muncul **2× berturut** (`BT_SPO2_STABLE_READS`): pasangan frame berurutan di buffer lewat `btStableCand()` (notifikasi & buffer sebelum tombol), atau baseline+1 polling (counter `candVal/candOk` — baseline dianggap konfirmasi pertama). Saat diterima: `values = { …, spo2, heartRate: null }` (PR mentah layout non-SFLOAT tidak dipercaya). Frame tunggal tidak pernah diterima; byte gelombang yang berfluktuasi menolak dirinya sendiri. Log: `kandidat 98 (konfirmasi 1/2)`, `DITERIMA (kandidat stabil)`, `via notifikasi/polling read (kandidat stabil)`.
- **Timbangan format IF/MovingLife (mis. Onemed IF20250A, OEM `IF_B*`)**: `parseWeight` mencoba **tanda-tangan IF lebih dulu** — panjang ≥15 byte, status `@14` ∈ {0x02 turun, 0x03 stabil}, `u16 BE @8 ÷10` = kg (20–300) → `{ weightKg, stable, format: 'if-be' }`; selanjutnya fallback WSS SIG (0x2A9D). Hanya **kg** yang dipakai (BIA/lemak via char `fff3` tidak pernah dilanggan). **TANPA gerbang konfirmasi** (keputusan user: alat auto-off, data tak boleh tertunda) — frame pertama yang lolos `plausible` (20–300) + segar langsung diterima/diteruskan; nilai berikutnya yang berbeda **menimpa** (data terakhir menang). `btPickScale()` = frame ok terakhir buffer. Blok `BT_SCALE_CONFIRM_READS`/`scaleGate`/gerbang 3× sudah **dihapus**. Service vendor `0xFFF0` sudah di `optionalServices`, sniff memilih `fff1` (notify).
- **Format timbangan IF_B2A TERKONFIRMASI (capture 20.24/20.25) + diagnostik**: device hanya punya service `0xFFF0` (tanpa profil WSS) → sniff `0000fff1` (read,notify). `readValue` char = **buffer 128 byte seluruhnya nol** — baseline/polling TIDAK membawa bobot; **notifikasi** membawa frame nyata. **Cabang `format:'if-b2a'`** di `parseWeight`: frame **14 byte** `10 00 00 c5 0e 03 80 <hi> <lo> …` → **berat = u16 BE @7 ÷10 kg**, signature `len ≥14 && byte0===0x10 && byte6===0x80` + rentang 20–300 (gerbang kedua). Bukti stream: `bd 06 → 70.1`, `24 04 → 54.8` (transien saat injak), `de 06 → 73.4` (stabil, frame diulang) — frame diterima saat muncul (tanpa gerbang), auto-apply per-frame menimpa sampai nilai akhir. **Beacon 20B** `10 00 00 c5 1f 03 82 00 68 62 00 8d …` (byte6=0x82) **bukan bobot** (identik lintas sesi, termasuk saat layar 73,5 & 72,9) → ditolak signature. `parseWeight` tetap melampirkan **`cands`** (scan seluruh buffer, LE/BE × ÷10 lalu ÷1, rentang 200–3000/20–300, maks 10, format `@7BE/10=73.3`) saat GAGAL — **hanya log teknisi, tidak pernah auto-apply**; jangan menambah cabang auto-accept dari tebakan offset tanpa bukti byte. **Urutan pakai: Connect dulu → baru berdiri** (frame 14B hanya dipancar selama pengukuran berlangsung; sesi 20.13 tanpa frame = tidak ada pengukuran saat itu). Log: `btParseFrame` memakai `hexDump(dv, 256)` + `len` di baris `frame`/`baca` baseline/polling; path read (`keep=false`) tidak mencatat baris `frame` sendiri (rangkuman `baca` sudah memuat hex+hasil); **throttle frame**: frame identik beruntun (act `frame`, who+msg sama, ≤3 dtk) hanya dicatat sekali — stream timbangan memancarkan ±8 frame identik/detik dan tanpa throttle baris `sniff`/koneksi terusir dalam hitungan detik (buffer/parser/auto-apply tetap jalan tiap frame); `btLogPush` cap **60**; label flags hex asli (`flags 0x10`). Uji 23b/23c di `test-bt.js` memakai byte asli hasil capture.
- **Auto-kirim bobot (timbangan auto-off)**: listener notifikasi saat **idle** (tanpa pengukuran berjalan) → `btAutoApply()` khusus `scale`: frame valid pertama → event `sf2w:bt-auto` (dedupe `h.autoSentKg` — nilai sama tidak dikirim ulang) → `onAutoValue` di komponen mengisi `form.weightKg` + tag Alat + chip Terukur **tanpa menunggu tombol**; form di-update per-frame, **toast di-debounce 2,5 dtk** (hanya nilai akhir). Saat sedang mengukur, `h.onFrame` diprioritaskan; setelah settle, frame lanjut lewat auto (overwrite). Gerbang `selected` & `d.measuring` tetap di `onAutoValue`.
- **Pasangan tersimpan & auto-reconnect (khusus alat, terutama timbangan)**: `requestDevice` (sekali klik per sesi — keamanan Chrome) → device disimpan di `BTPaired[key]` + `sessionStorage['sf2w_pair_'+key]` (`device.id`). Connect berikutnya **tanpa chooser** (`fromPair`). `navigator.bluetooth.getDevices()` (feature-detected, `btRestorePair`) saat mount → langsung `btStartReconnect('scale')`. Loop reconnect: retry tiap **1,5 dtk** (dulu 4 dtk — jendela blink alat hanya ±3 dtk, interval 4 dtk melewatinya; log throttle: awal + tiap ke-5), sukses → event `sf2w:bt-connected` → `onReconnected` (kartu "…(auto)", note, toast); GATT naik tapi char gagal → `fatal` → stop + `sf2w:bt-reconn-failed`. `gattserverdisconnected` scale → restart loop (listener dijaga `device._sf2wDisc` anti-dobel). **Mode `silent`/`reconnecting` TIDAK PERNAH jatuh ke simulasi**; pasangan tidak cocok (GATT naik, discovery gagal) → `btUnpair` + `rechoose` (pilih ulang, tanpa paksa input manual). `resetForm` **tidak** memutus koneksi scale (listening bertahan lintas pasien); `enableManual` → `btDisconnect` + `btUnpair`; unmount → stop semua loop reconnect.
- **Putus koneksi saat pengukuran**: `bluetoothMeasure` mendaftar listener `gattserverdisconnected` di `handle.device` (dibersihkan di `cleanup`) — key `scale` dengan `lastScaleFrame` (frame ok terakhir, direkam di `onFrame`/`pollRead`) → settle `ok:true` (bobot terakhir sebelum putus yang dipakai); selain itu → `ok:false` alasan `Koneksi terputus sebelum data diterima …` (wait-loop tidak menggantung 120 dtk). `onDisconnected` komponen **tidak** mereset `measured` (sumber save tetap `Bluetooth` setelah alat auto-off) dan chip `!connected && error` menampilkan **Terputus** (bukan 'Manual').
- Tombol **Mulai Pengukuran** muncul per kartu alat setelah terhubung; hasilnya mengisi field form (belum auto-save — perawat tetap klik Simpan). Frame yang tiba sebelum tombol (buffer ≤90 detik) boleh dipakai; buffer dikosongkan setelah sukses agar "Ukur Ulang" baca data baru.
- Diagnostik: `btLogPush()` mencatat koneksi/UUID/props/frame hex ke `sessionStorage` + event `sf2w:bt-log`; panel "Detail log Bluetooth" di halaman Pemeriksaan untuk laporan teknisi. Parser mengikuti spesifikasi SIG (BP `0x2A35` SFLOAT+flags, PLX `0x2A5E/0x2A5F`, HTP `0x2A1C` timestamp @5, WSS `0x2A9D` + feature `0x2A9E`).

## 3. Domain & Konvensi
- FIT = `sistolik < 140 && suhu < 37.5` (fungsi `calcStatus`). Selain itu UNFIT.
- Alert merah: tensi > 140/90, suhu ≥ 37.5°C, SPO2 < 95.
- Sesi login di `sessionStorage` (`sf2w_session`, `sf2w_user`) — jangan pindah ke localStorage permanen (NFR `prd.md`).
- Halaman **Pengaturan** (`#/pengaturan`, komponen `PengaturanPage`): memilih dokter/perawat jaga dari daftar `MOCK.dutyOfficers` (disinkronisasi dari BE sheet `DutyOfficers`, field `id/name/role/initials/defaultName/defaultRole`); pilihan disimpan di `sessionStorage['sf2w_duty']` (id), tombol Kosongkan menghapusnya. **Nama dan role petugas bisa disunting** (input & select, event `@change` → `saveOfficer()`); tersimpan di sheet `DutyOfficers` via API. Di frontend, hasil override disimpan sebagai map per-id `{name, role}` di `sessionStorage['sf2w_duty_overrides']` (JSON) dan menggantikan tampilan di baris daftar, kartu "Sedang jaga", serta blok profil kanan header — input nama dikosongkan → BE mengembalikan ke nama/role asli; **header AppShell**: greeting statis `Halo Portizen`, subjudul statis `Silahkan cek kesehatan anda`, sedangkan blok profil kanan (avatar inisial + nama + role) **mengikuti pilihan duty** — `duty ? duty.name : auth.user?.name` (juga `role`/`initials`, fallback user login bila belum dipilih; **nama/role suntingan menang** via `sf2w_duty_overrides`); AppShell baca `sessionStorage['sf2w_duty']` + listener `sf2w:duty-changed`; **sudah ikut payload record** via `readDuty()` (field `examiner`/`examinerRole`, kosong bila belum dipilih). Menu sidebar "Pengaturan" (`genMenu`) menunjuk key `pengaturan` — jangan kembalikan ke `dashboard`.
- Event bus via CustomEvent di `window`: `sf2w:pick-employee`, `sf2w:toast`, `sf2w:duty-changed`, `sf2w:employee-added` (detail = objek karyawan baru; didispatch `PemeriksaanPage.submitEmployee`, didengar App root untuk memperbarui daftar `employees`).
